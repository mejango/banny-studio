# Portable Banny Live bridge

`banny-live-bridge.py` lets a participant join a Banny Live room from Windows,
Linux, or macOS with Python 3.8 or newer. It uses only Python's standard
library. The canonical downloadable script is bundled into the room site at:

```text
https://your-room-host.example/banny-live-bridge.py
```

Download that file beside the `avatar.json` generated by the room's join page.
If the room is allowlisted, also download its generated
`banny-room-credentials.json`. On macOS or Linux, lock the credentials first:

```sh
chmod 600 banny-room-credentials.json
```

Start your local `banny.agent.v1` API, then run:

```sh
python3 banny-live-bridge.py \
  'https://your-room-host.example/rooms/room-id/live' \
  --agent 'http://127.0.0.1:7331' \
  --name 'My Banny' \
  --character './avatar.json' \
  --credentials-file './banny-room-credentials.json'
```

For a public room, omit `--credentials-file`. The credentials JSON may contain
only `identity`, `invite`, and `agent_token`, each as a string or `null`.
Invitation and agent tokens deliberately have no command-line flags, so they do
not enter shell history or process listings.

The room URL may be `/rooms/<id>`, `/rooms/<id>/live`, `/rooms/<id>/join`, or
`/v1/rooms/<id>`. Plain HTTP is accepted only for numeric loopback. A local AI
must likewise use `127.0.0.0/8` or `::1` by default; `localhost` is deliberately
not resolved. An explicitly remote AI requires both HTTPS and
`--allow-remote-agent`.

Use `--json` for a JSON ready record on stdout and skipped-decision records on
stderr. `Ctrl-C`, SIGTERM, and Windows Ctrl-Break trigger a best-effort room
leave. Host end or kick revokes the participant session with HTTP 401, which is
treated as a clean exit.

## Security and current limitations

- Room and agent redirects are refused. All JSON and HTTP bodies are bounded,
  and decision responses are correlated and validated before submission.
- A room poll GET and its exact correlated decision submission are retried at
  most three times for transient socket, temporary DNS, connection, or timeout
  failures and HTTP 502/503/504. Poll retries wait 150/300 ms within one
  monotonic 35-second budget; submission retries replay the identical bytes
  after 50/100 ms within the context's original absolute deadline and a
  10-second cap.
  Join, leave, local-AI calls, redirects, other HTTP statuses, TLS failures,
  malformed or oversized messages, and cancellation are never retried.
- Any timeout, HTTP error, malformed response, or invalid intent from the local
  AI becomes one correlated no-op, allowing the authoritative room sequence to
  continue without replaying stale context.
- The script ignores ambient HTTP proxy variables so loopback credentials never
  reach an unexpected proxy. The machine must be able to connect directly to
  the room host.
- Retry scheduling and per-attempt timeouts share a monotonic deadline, but
  Python's standard `urllib` timeout is a socket-operation timeout rather than
  a hard wall-clock deadline against a peer that continuously drip-feeds bytes.
  Body limits still cap memory; exact hard-deadline parity requires a native
  transport.
- POSIX ownership and `0600`-style permissions are enforced for credentials.
  Python's standard library cannot reliably audit Windows ACLs; Windows users
  should use the file's Security properties to restrict it to their account.
- Avatar JSON is structurally validated locally. The room host remains the
  authority for its current eyes, mouth, and outfit catalog names.
- An uncatchable stop such as `SIGKILL`, process termination from Task Manager,
  power loss, or a network partition cannot send `leave`; the room's session
  lease eventually releases the seat.

From the Banny Studio checkout:

```sh
python3 -m unittest discover -s Examples/BannyLiveBridge/tests -v
```
